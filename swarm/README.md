# SwarmShield v2: Track B software lane (`swarm/`, `dashboard/`, `scripts/run_*.ps1`)

Track B, LANE=SW: hub, drone runtime, MissionApp, director, observer, dashboard, scenarios, run checker. Progress log:
`docs/progress/swarm_log.md` (evidence of each result: `docs/progress/evidence/`). Commands below run from the repo root. Non-kinetic only: search and rescue, survey, surveillance ("OBJ-1" is a drifting boat).

**Status: verified on the MOCK engine and on Track A's REAL `ClusterEngine`** (single machine, over the UDP hub; the
Neurick board and a multi-laptop run are not covered). Mock runs are labelled everywhere (`data.mock = true`, red banner
on the dashboard). Numbers from a mock run describe the simulator, never the real engine.
One Track A engine bug needs the opt-in `--shim-obs-conflict` flag (see below).

## Setup (once)

```powershell
py -3 -m venv .venv
./.venv/Scripts/python -m pip install -r swarm/requirements.txt
./.venv/Scripts/python -m pytest swarm -q          # all green
```

Use `./.venv/Scripts/python` for everything (never a bare `python`/`pip`). `set PYTHONUTF8=1` is applied by the launchers.

## Run it

Single laptop, everything simulated (fastest way to see it):

```powershell
./scripts/run_station.ps1 -MockNodes
```

Then open http://localhost:8080 and press **Start scenario** (`demo`). Equivalent without the script:
`./.venv/Scripts/python -m swarm.station --mock-nodes`.

Several laptops (laptop A = station, B/C = drones), hotspot `swarmshield`, all on one Wi-Fi:

```powershell
# laptop A (find its Wi-Fi IPv4 with ipconfig; ignore VMware 192.168.x adapters)
./scripts/run_station.ps1 -RunId demo-final
# laptop B and C
./scripts/run_nodes.ps1 -HostName B -Hub <A-IP>:47000 -RunId demo-final
./scripts/run_nodes.ps1 -HostName C -Hub <A-IP>:47000 -RunId demo-final
# laptop A also hosts c1-d4 and c2-d5:
./scripts/run_nodes.ps1 -HostName A -Hub 127.0.0.1 -RunId demo-final
```

Any device on the network can open `http://<A-IP>:8080`. Windows asks once to allow Python: choose **Private**
networks. `./scripts/firewall_rules.ps1` only PRINTS the netsh commands; it never runs them.

Ports: hub UDP 47000, hub control HTTP 47001, observer UDP 47002, dashboard/observer HTTP 8080.

| `swarm/sensors.py` | WORLD + Gaussian noise -> OBS txs; `false_obs` fault |
| `swarm/node.py`, `node_host.py` | one drone / all drones of a host; handoff trigger; exports ledgers |
| `swarm/director.py` | world physics (WORLD 10 Hz) + YAML scenario runner |
| `swarm/observer.py` | UDP events -> dedupe -> SSE `/events`, `/state`, metrics, `events.jsonl`, all spec 11.8 endpoints |
| `swarm/station.py` | hub + director + observer in one process (flags `--no-hub --no-director --no-observer --mock-nodes`) |
| `swarm/scenarios/*.yaml` | `demo` (acts 1-4), `handoff`, `kill_master`, `partition`, `equivocate_sim`, `false_obs` |

## Check a run

```powershell
./.venv/Scripts/python -m swarm.tools.check_run runs/<runId>
```

Prints PASS / FAIL / SKIP for Acts 1-4, measured latencies (observer receive clock only) and which checks need the
real engine. Exit code 1 if any act FAILs.

Act 1 handoff `xc_sent -> xc_verified -> ownership(OBJ-1 -> C2) -> xc_acked`; Act 2 kill `-> master_changed` within 6 s
`-> commits continue`; Act 3 `evidence -> revoked` within 3 heights (simulated equivocator); Act 4 partition `->
contingency ENTER x2 ->` no OBJ-2 handoff while cut `-> heal -> EXIT x2 ->` deferred handoff completes.

## Real engine (Track A's `ClusterEngine`)

Needs from Track A: `ledger/` (the `swarmledger` package), `config/mission.json` (generated by `scripts/gen_keys.py`),
`.keys/<name>.json` (private mission keys, gitignored, NEVER commit or share) and `contracts/deployments/mst-testnet.json`
(deployment record, served at `/deployments`). Without `config/mission.json` the dev fixture `config/mission.dev.json` (fake
addresses, mock engine only) is used. One-time: `./.venv/Scripts/python -m pip install eth-keys eth-utils pycryptodome`.

```powershell
# laptop A: station (dashboard) + its drones c1-d4, c2-d5
./scripts/run_station.ps1 -RunId demo-final
./scripts/run_nodes.ps1 -HostName A -Hub 127.0.0.1 -Engine real -Keys .keys -ShimObsConflict -RunId demo-final
# laptops B, C
./scripts/run_nodes.ps1 -HostName B -Hub <A-IP> -Engine real -Keys .keys -ShimObsConflict -RunId demo-final
./scripts/run_nodes.ps1 -HostName C -Hub <A-IP> -Engine real -Keys .keys -ShimObsConflict -RunId demo-final
```

Single-machine test of everything at once: `station`, then
`PYTHONPATH=ledger ./.venv/Scripts/python -m swarm.node_host --host A,B,C --engine real --keys .keys --mission config/mission.json --shim-obs-conflict`.
The hardware board is not started by `node_host --engine real` (it is a real device; cluster 1 runs on 4 full drones,
weight 12 of 13, quorum 9).

**Track A bug and the shim.** `swarmledger.engine._build_block` keeps only ONE OBS per block: `_conflict_key` returns `None`
for OBS, so after the first OBS `None in keys` is true. The fused track then lags badly and handoffs come late.
`--shim-obs-conflict` gives each OBS a unique conflict key from inside my runtime (their file is not edited). Track A fix:
`if k is not None and k in keys: continue`. Once fixed, the shim is a harmless no-op and the flag can be dropped.
`pytest swarm/tests/test_real_engine.py` reproduces the bug and checks the shim (it skips itself once fixed upstream).

Chain events: Track A's `chain_client` sends events to UDP `127.0.0.1:47002`, so run it on laptop A next to the station.
The dashboard's MST panel reads `/deployments` (contracts, this mission's tx links, roster-hash match).

## Troubleshooting

- Dashboard empty from another device: Firewall (Private), network profile Private, use the Wi-Fi IPv4 not a VMware one.
- Nodes do not appear: hub `curl.exe http://<A-IP>:47001/topology` should list them; UDP 47000 must be reachable.
- "MOCK ENGINE RUN" banner is expected until Track A's engine is plugged in.
- Ctrl+C on a node process exports its ledger to `runs/<runId>/` and uploads it to the observer.
